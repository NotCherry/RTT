# Codex OOM investigation — 2026-09-14

## Finding

The desktop crash at 08:44:20 CEST was a system-wide out-of-memory event, not
an unbounded memory leak in robot training. The kernel selected a ChatGPT/Codex
process as the victim. The machine had no swap, so a short concurrent workload
had no safety margin.

## Evidence

- Previous-boot kernel logs contain `gnome-shell invoked oom-killer` followed
  by `Out of memory: Killed process 50489 (ChatGPT)`.
- At the kill, anonymous memory totaled about 11.3 GiB and only about 145 MiB
  was free. Swap was `0 kB`.
- The largest resident processes included isolated browser content at 804,
  705, 705, and 552 MiB; Firefox at 462 MiB; the killed ChatGPT process at
  609 MiB; and several additional ChatGPT, browser, Python, and Node workers.
- The ChatGPT application cgroup recorded a 1.9 GiB peak. The robot backend
  was 261 MiB at the OOM snapshot.
- The concurrent verification command added a Python test process and two
  frontend workers (roughly 476 MiB combined in the kernel snapshot). It was a
  pressure trigger on an already full machine, not the dominant consumer.
- After restart, the Codex Electron host logged
  `MaxListenersExceededWarning: Possible EventEmitter memory leak detected`
  for `WebContents` destroyed listeners. That warning belongs to the desktop
  host, outside this repository, and should be reported upstream with the
  timestamp and journal excerpt.

## Repository training probe

A single-process probe repeatedly created a simulation session, trained the
same multi-segment gesture for 50 epochs, closed the session, forced garbage
collection, and sampled process RSS. Across 12 iterations RSS warmed from
440.5 MiB to 506.5 MiB, then remained exactly 506.5 MiB for iterations 6–12.
This plateau is consistent with PyTorch/PyBullet allocator and thread-pool
warm-up; it does not show unbounded retention across training runs.

The focused backend test peaked at about 473 MiB RSS. The frontend focused
suite peaked at about 204 MiB with one worker. Routine frontend tests now use a
single worker to reduce avoidable memory pressure. Tests should be run
sequentially on this no-swap host.

## Product bug related to pressure

Multi-segment gesture training silently raised every user budget below 1,200
epochs to 1,200. That made supposedly small tests and user runs longer than
requested. The override has been removed; training now executes the exact
validated epoch count supplied by the user.
